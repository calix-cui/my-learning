## 1. 对象、数据类型与容器

**1.1 先练｜`list` 和 `tuple` 有什么区别？元组能当字典键吗？**

列表可以改变元素和长度。元组的槽位固定，槽位指向的对象仍可能可变。元组只有在所有元素都可哈希时才能当键，因此 `("tool", 1)` 可以，`("tool", [])` 不行。消息历史通常用列表，工具缓存键可以用由不可变标识组成的元组。[Python 数据模型](https://docs.python.org/3/reference/datamodel.html)

**1.2 先练｜`dict` 为什么查找快？哈希冲突怎么处理？**

通常先算哈希并找到候选位置，再用相等性判断区分键；平均查找接近 O(1)，大量冲突等极端条件下可能退化到 O(n)。CPython 使用开放寻址探测，删除后的占位可能仍用于维持探测链。Python 3.7 起字典保持插入顺序是语言保证，探测和扩容属于实现细节。定义可哈希对象时，相等对象必须有相同哈希值。[Python 映射类型](https://docs.python.org/3/library/stdtypes.html#mapping-types-dict) · [CPython 字典实现](https://github.com/python/cpython/blob/3.14/Objects/dictobject.c)

**1.3 先练｜赋值、浅拷贝和深拷贝怎么区分？**

赋值创建另一个名字到同一对象的绑定。浅拷贝新建外层容器，内部元素仍共享。深拷贝递归复制对象图，用备忘记录处理循环和重复引用。Agent 准备分支上下文时，`messages.copy()` 后仍可能改到原有消息里的嵌套字段。我会根据变更范围复制字段，或用不可变结构表达共享数据。[Python copy](https://docs.python.org/3/library/copy.html)

**1.4 先练｜可变默认参数为什么会串数据？`dataclass` 里怎么写？**

函数默认参数在定义时求值，`def run(history=[])` 的空列表会被后续调用复用。普通函数可以在 `history is None` 时创建列表，数据类字段使用 `field(default_factory=list)`。代码里用 `history or []` 会把调用者传入的空列表也替换掉。[函数定义](https://docs.python.org/3/reference/compound_stmts.html#function-definitions) · [dataclasses](https://docs.python.org/3/library/dataclasses.html#default-factory-functions)

**1.5 延伸｜`is`、`==`、`None` 和假值怎么区分？**

`is` 比身份，`==` 比相等性。用 `value is None` 判断空值，用键是否存在区分 JSON 的「缺失字段」和显式 `null`。例如工具返回 `count=0` 时应保留 0，直接写 `value or default` 可能掩盖有效值。[Python 比较运算](https://docs.python.org/3/reference/expressions.html#comparisons)

## 2. 函数、闭包与装饰器

**2.1 先练｜函数是对象有什么实际用途？`*args` 和 `**kwargs` 做什么？**

函数能赋值、传参、返回，也能存入注册表。工具分派可以用受控的 `dict[str, Callable]` 查函数。定义参数时，`*args` 收集额外位置参数，`**kwargs` 收集额外关键字参数；调用时它们用于解包。工具 JSON 应先校验并过滤可用字段，再传给函数。[Python 函数定义](https://docs.python.org/3/reference/compound_stmts.html#function-definitions)

**2.2 先练｜闭包的延迟绑定是什么？循环注册工具时会踩什么坑？**

闭包使用的是变量绑定，调用时才读取其值。在循环中用 `lambda: name` 注册多个回调，调用时可能全读到末次的 `name`。可用 `lambda name=name: name` 保存每次值，或用工厂函数为每次注册创建独立作用域。闭包内部要重新绑定外层局部变量时可用 `nonlocal`。[Python FAQ](https://docs.python.org/3/faq/programming.html#why-do-lambdas-defined-in-a-loop-with-different-values-all-return-the-same-result)

**2.3 先练｜装饰器什么时候运行？为什么要用 `functools.wraps`？**

函数定义时应用装饰器，等价于把函数传给装饰器并重新绑定名字。包装函数的主体通常在调用时执行。带参数装饰器多一层工厂，用来绑定超时或日志配置。`wraps` 保留名称、文档等元数据和 `__wrapped__`，方便工具框架检查签名。异步包装器要在计时或捕获异常的范围内 `await` 原函数，否则可能只测到创建协程的时间。[Python functools](https://docs.python.org/3/library/functools.html#functools.wraps)

```python
import asyncio
import inspect
from functools import wraps
from typing import Awaitable, Callable, ParamSpec, TypeVar

P = ParamSpec("P")
R = TypeVar("R")


def with_timeout(seconds: float):
    def decorate(fn: Callable[P, Awaitable[R]]) -> Callable[P, Awaitable[R]]:
        @wraps(fn)
        async def wrapped(*args: P.args, **kwargs: P.kwargs) -> R:
            async with asyncio.timeout(seconds):
                return await fn(*args, **kwargs)

        return wrapped

    return decorate


@with_timeout(1)
async def lookup(query: str) -> str:
    return query.upper()


assert inspect.signature(lookup).parameters["query"].annotation is str
assert asyncio.run(lookup("python")) == "PYTHON"
```

## 3. 迭代器、生成器与资源清理

**3.1 先练｜可迭代对象、迭代器和生成器怎么区分？**

可迭代对象能交给 `iter()` 取得迭代器。迭代器用 `next()` 依次取值，耗尽时抛出 `StopIteration`。生成器是通过带 `yield` 的函数或生成器表达式创建的一类迭代器，能暂停并恢复执行。生成器通常只能消耗一次；日志代码先 `list(stream)` 会把下游需要读取的流提前用完。[Python 迭代器类型](https://docs.python.org/3/library/stdtypes.html#iterator-types)

**3.2 先练｜`yield`、`yield from`、`async for` 分别适用什么场景？**

`yield` 每次交出一条结果并保留执行位置。`yield from` 将同步迭代委托给另一个迭代对象。读取异步 HTTP 数据时可以用异步生成器和 `async for`，等待下一批数据时允许其他任务运行。连接或流可能提前关闭，资源清理要放进 `with`、`async with` 或 `finally`。[Python yield 表达式](https://docs.python.org/3/reference/expressions.html#yield-expressions) · [contextlib](https://docs.python.org/3/library/contextlib.html)

**3.3 延伸｜`with` 的底层协议是什么？怎样保证出错时释放资源？**

同步上下文管理器实现 `__enter__` 和 `__exit__`，异步版本使用 `__aenter__` 和 `__aexit__`。成功进入后，退出方法接收异常信息；同步退出方法返回真值会抑制异常。用它管理 HTTP 连接、文件和订阅。异步生成器若由调用者提前停止消费，可用 `contextlib.aclosing()` 保证离开作用域时关闭。[Python 上下文管理器](https://docs.python.org/3/reference/datamodel.html#context-managers) · [contextlib.aclosing](https://docs.python.org/3/library/contextlib.html#contextlib.aclosing)

## 4. 类、类型标注与运行时校验

**4.1 延伸｜`__new__`、`__init__`、`__call__` 分别什么时候执行？**

`__new__` 创建对象，`__init__` 初始化已创建的实例，`__call__` 支持用函数语法调用实例。带配置和状态的工具可做成可调用对象。元类控制类的创建，普通工具注册通常用显式注册表或类装饰器就够。[Python 数据模型](https://docs.python.org/3/reference/datamodel.html)

**4.2 先练｜怎么为多个 LLM 客户端定义共同接口？**

用 `Protocol` 声明业务需要的方法和返回结构。实现只要满足约定，静态检查器就能检验相容性，Runtime 可直接换用生产适配器或测试替身。`TypedDict` 描述字典字段，`dataclass` 适合内部配置或状态，外部数据用 Pydantic 等工具做运行时校验。[Python typing](https://docs.python.org/3/library/typing.html)

**4.3 先练｜模型声称返回 JSON，为什么还是要校验？**

JSON 解码成功只代表语法可读。工具参数还要检查类型、缺失或多余字段、数值范围及业务权限。Pydantic 的宽松模式可能转换类型，例如把字符串数字转为整数；有严格契约时可用严格模式，对多余字段可配置 `extra="forbid"`。用户身份与会话范围由服务端上下文决定。[Pydantic 模型](https://docs.pydantic.dev/latest/concepts/models/) · [Pydantic 严格模式](https://docs.pydantic.dev/latest/concepts/strict_mode/)

## 5. 并发、GIL、超时与取消

**5.1 先练｜进程、线程、协程怎么选？GIL 怎么回答才准确？**

网络模型和异步工具适合事件循环并发，只有同步接口的阻塞 SDK 可以隔离到线程，纯 Python 的 CPU 密集任务可考虑进程池，并计算数据序列化和进程开销。在启用 GIL 的 CPython 中，同一解释器通常同时只有一个线程执行 Python 字节码，阻塞 I/O 和部分原生扩展会释放 GIL。CPython 3.13 起有可选自由线程构建，回答时要交代运行环境。跨步骤的共享更新仍需同步。[Python threading](https://docs.python.org/3.14/library/threading.html) · [自由线程构建](https://docs.python.org/3.14/howto/free-threading-python.html)

**5.2 先练｜`await` 和 `create_task()` 有什么区别？`async def` 里能用 `time.sleep()` 吗？**

调用协程函数会得到协程对象。直接 `await` 等待这个协程完成，`create_task()` 把它加入事件循环调度，可以与其他任务并发。异步函数里调用 `time.sleep()` 或阻塞 HTTP 客户端会阻塞事件循环线程。替换为原生异步 I/O，或用 `asyncio.to_thread()` 隔离已知的阻塞 I/O。[Python asyncio Tasks](https://docs.python.org/3/library/asyncio-task.html)

**5.3 先练｜什么时候用 `TaskGroup`，什么时候用 `gather()`？**

Python 3.11 起的 `TaskGroup` 适合一组共享生命周期的任务。某子任务因普通异常失败时，TaskGroup 会取消其他任务，等它们收尾，并以异常组报告。默认的 `gather()` 会向等待者传播首个异常，但不会因某个任务报错自动取消其他任务。独立只读工具允许部分成功时，可以在各任务内明确处理预期错误，再按调用 ID 汇总。[Python asyncio 并发任务](https://docs.python.org/3/library/asyncio-task.html#running-tasks-concurrently)

**5.4 先练｜超时和取消意味着远端工具已经停了吗？**

`asyncio.timeout()` 通过取消当前协程限制该段等待，在上下文外报告 `TimeoutError`。协程用 `finally` 清理，并在捕获 `CancelledError` 后继续传播取消。取消等待 `to_thread()` 不会强制停止已运行的线程；HTTP 超时后远端也可能仍在执行。修改数据的工具要依靠幂等键和状态查询决定能否重试。[Python asyncio 取消与超时](https://docs.python.org/3/library/asyncio-task.html#task-cancellation) · [concurrent.futures](https://docs.python.org/3/library/concurrent.futures.html#concurrent.futures.Future.cancel)

**5.5 先练｜十个工具并行调用怎么限制并发？多个 Worker 同时写怎么办？**

独立只读任务可用 `asyncio.Semaphore` 限制在途量。面对很大的任务流，用有界队列和固定数量的 Worker，同时约束待处理量。`asyncio.Lock` 适用于同一事件循环内的协程共享状态；多个进程写数据库时，依靠事务、唯一约束或条件更新守住一致性。例如审批只允许从 `pending` 原子更新一次。[Python asyncio 同步原语](https://docs.python.org/3/library/asyncio-sync.html) · [异步队列](https://docs.python.org/3/library/asyncio-queue.html)

```python
import asyncio
from collections.abc import Awaitable, Callable


async def run_reads(
    calls: list[Callable[[], Awaitable[str]]],
    limit: int,
    timeout: float,
) -> list[str]:
    if limit < 1:
        raise ValueError("limit 必须大于 0")

    slots = asyncio.Semaphore(limit)

    async def run_one(call: Callable[[], Awaitable[str]]) -> str:
        async with slots:
            async with asyncio.timeout(timeout):
                return await call()

    async with asyncio.TaskGroup() as group:
        tasks = [group.create_task(run_one(call)) for call in calls]

    return [task.result() for task in tasks]
```

这段代码适合数量有限的只读任务。超时从取得并发槽位后开始计时，请求级总预算可以在调用方另设。任务失败采用整批取消语义，返回顺序与输入一致。

## 6. 异常、内存与排障

**6.1 延伸｜`try/except/else/finally` 怎么用？如何保留错误根因？**

`except` 捕获能处理的具体异常，`else` 适合放在 `try` 正常完成后才执行的逻辑，`finally` 用来清理。用 `raise ToolError("参数格式错误") from exc` 包装底层异常并保留因果链。对外提示可以说清哪一步失败，日志通过 `run_id` 和 `tool_call_id` 定位，去掉密钥与不必要的用户内容。[Python 异常处理](https://docs.python.org/3/tutorial/errors.html)

**6.2 延伸｜CPython 怎么管理内存？循环引用能回收吗？**

CPython 使用引用计数，并用循环垃圾回收器补充处理不可达的引用环。还被全局缓存、任务、回调或队列引用的对象仍然可达，调用 `gc.collect()` 无法让它们消失。排查长时间运行的 Agent 时，先看是否无限保留消息、工具结果或未清掉任务，再用 `tracemalloc` 比较快照。资源释放用显式关闭或上下文管理器。[Python gc](https://docs.python.org/3/library/gc.html) · [tracemalloc](https://docs.python.org/3/library/tracemalloc.html)

## 7. HTTP、FastAPI 与流式输出

**7.1 先练｜FastAPI 路由用 `def` 还是 `async def`？**

依赖原生异步 I/O 时用 `async def` 并在调用点 `await`。同步 I/O 可以放到由 FastAPI 在线程池运行的普通 `def` 路由。异步路由直接调用一个自定义普通函数时，FastAPI 不会自动替这个调用切线程。HTTP 客户端按服务生命周期复用连接池。[FastAPI 并发说明](https://fastapi.tiangolo.com/async/) · [HTTPX 客户端](https://www.python-httpx.org/advanced/clients/)

**7.2 先练｜HTTPX 超时有哪几种？什么时候能重试？**

连接、读取、写入和等待连接池各有超时。读取超时限制等待数据的时间，整个 Agent 运行还需单独的总预算。短暂网络故障或上游允许重试的状态可以在预算内退避重试。身份认证、参数错误和余额不足应让调用方修复原因。对有副作用的操作，先确认执行状态或使用下游支持的幂等机制。[HTTPX 超时](https://www.python-httpx.org/advanced/timeouts/)

**7.3 先练｜流式回复为什么会断字、丢帧或一次性到达？怎样恢复？**

网络块边界可能切在 UTF-8 字符中间或 SSE 帧中间。客户端用增量解码并缓冲，按完整事件分隔符处理，服务端可用注释心跳维持活跃，还需检查代理缓冲。需要断点恢复时，可以保存事件序号，并根据客户端最后处理的序号回放。浏览器 `EventSource` 走自己的重连协议；POST + `fetch` 的实现要显式携带游标并管理重连。慢消费者可用有界缓冲保护内存。[WHATWG SSE 规范](https://html.spec.whatwg.org/multipage/server-sent-events.html)

**7.4 延伸｜工具结果很多或 API 返回结构变了，怎么避免拖垮下一轮？**

适配层先校验允许的字段和版本，必需字段缺失时生成结构化错误。大结果分页、限制字节数、提取有用字段，把短摘要和引用交给模型。诊断时记录版本、响应大小和耗时。测试分别覆盖坏 JSON、缺字段、未知字段和超大响应。

## 8. 工具调用、幂等与测试

**8.1 先练｜怎么解释 Python Agent 的最小执行循环？**

用列表保存上下文，用注册表保存可调用工具。每轮向模型提供工具声明，解析调用 ID、名称和参数，经校验和授权后执行，把结果按 ID 放回上下文。遇到最终答复就结束，需要授权就持久化步骤并挂起，达到轮数、时限或失败上限就终止。一轮内可以执行多个互不依赖的只读工具，有依赖或修改共享状态的操作要按顺序处理。[项目完整口述](../Python%20Agent%20开发面试问答.md)

**8.2 先练｜用户刷新页面或重复点审批，怎样避免重复执行？**

把 `run_id`、步骤的业务操作 ID、审批决定和执行结果持久化。用唯一约束或原子状态更新争抢执行资格，并在重试时沿用同一业务幂等键。若服务端在外部操作成功后、记录结果前崩溃，恢复时要向下游查结果或复用下游幂等键；本地去重本身解决不了这个故障窗口。

**8.3 先练｜怎么测试 Agent，避免每次跑 pytest 都扣模型额度？**

把模型客户端和工具实现作为依赖传入，测试用脚本化假模型依次返回「请求工具」「最终回答」，断言调用次数、工具 ID 和状态转换。适配器测试用 HTTPX `MockTransport` 校验请求并模拟超时与异常响应。少量真实模型验收检查供应商协议与实际行为。网络分片测试可以把一条含中文的事件拆成多块，断言内容和步骤序号保持正确。[HTTPX 模拟传输](https://www.python-httpx.org/advanced/transports/#mock-transports) · [pytest monkeypatch](https://docs.pytest.org/en/stable/how-to/monkeypatch.html)

## 9. 标准库与手写题

**9.1 先练｜怎么找出现频率最高的 K 个元素？**

先用 `collections.Counter` 统计，再用堆从不同元素里选前 K。设输入长 n，有 m 个不同元素，常见的固定大小小根堆方案在 `1 ≤ k ≤ m` 时用 O(n + m log(k+1)) 时间和 O(m + k) 空间。面试时问清并列顺序、空输入和 `k > m` 的要求。[标准库 Counter](https://docs.python.org/3/library/collections.html#collections.Counter) · [heapq](https://docs.python.org/3/library/heapq.html)

**9.2 先练｜怎么用 O(1) 的 `get` 和 `put` 实现 LRU？**

字典保存键到链表节点的映射，双向链表维护最近访问顺序。命中或更新时移动节点到最近端，超容量时从最久未访问的一端删除节点和对应键。使用 Python 标准库时可用 `OrderedDict.move_to_end()` 和 `popitem(last=False)`。工程中还要明确定义缓存键是否含用户和模型配置。[标准库 OrderedDict](https://docs.python.org/3/library/collections.html#collections.OrderedDict)

**9.3 延伸｜`deque`、`queue.Queue` 和 `asyncio.Queue` 选哪个？**

`deque` 便于两端快速增删，适合 FIFO 算法和维护最近 K 条记录。`queue.Queue` 提供线程间的同步阻塞队列。`asyncio.Queue` 用于同一事件循环中的生产消费，队列满时可以等待。多轮对话剪裁还要照看消息的时间顺序和工具请求与结果是否成对。[标准库 deque](https://docs.python.org/3/library/collections.html#collections.deque) · [线程队列](https://docs.python.org/3/library/queue.html) · [异步队列](https://docs.python.org/3/library/asyncio-queue.html)

**9.4 延伸｜如何判断一个人能否参加所有会议？**

把半开区间 `[start, end)` 按开始时间排序，相邻会议如果后一个开始早于前一个结束便冲突。时间复杂度 O(n log n)。先确认边界约定。例如 10:00 结束和 10:00 开始的两个会议是否可衔接，再覆盖空列表、重复区间和输入顺序打乱的用例。[蚂蚁秋招一面记录](https://www.nowcoder.com/feed/main/detail/6490526c86124f92b79a993e171f7222)

**9.5 延伸｜怎么把多个异步工具的结果按原顺序返回，怎样验证确实并发？**

可以用第 5 节的 `run_reads()` 做手写题。输入包含一个快任务和一个慢任务，结果仍按输入顺序排列。测试用 `asyncio.Event` 控制两个任务的开始和退出，并记录同时在途的峰值，覆盖 `limit=1`、空输入和超时。这样能把并发正确性与机器当时的执行速度分开检验。
