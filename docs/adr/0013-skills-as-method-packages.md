# ADR-0013：Skill 是可复用的「方法包」，不是权限包

- **状态**：已确认（2026-11-11）
- **背景**：阶段 7 的后半是「Skill」。MCP 已经把「能碰到什么」打通，但「该怎么干」还只能靠用户在对话里反复交代。
  `AGENTS.md` 要求先调研成熟做法、不要自造协议。
- **相关**：[`docs/skills.md`](../skills.md)、[`docs/tools.md`](../tools.md)、[`ADR-0011`](0011-tool-permissions-and-approvals.md)

## 决定

1. **形状照抄 Agent Skills**：一个技能 = frontmatter 元数据 + Markdown 正文；落库时拆成
   `slug/name/description/instructions/tools/icon` 六列。不自造 DSL。
2. **手动挂载，不做自动选择**：`conversations.skill_slug` 记录当前技能，用户在选择器里挑。
   自动选要么多一次模型调用、要么做成 `use_skill` 工具再进一层循环，两者都让「这次为什么走这个流程」难以解释。
3. **正文一次性注入 system prompt**，不做两段式按需加载；技能库变大再改。
4. **工具白名单只做减法**：`tools` 非空时，注册表只保留列出的工具（复用设置页关工具的 `disabled` 通道）。
5. **Skill 不提权**：不改变 `ToolLevel`，写/外网工具照旧审批。技能是方法与范围，不是权限。

## 代价

- 一次性注入正文：技能很多、正文很长时会一直占上下文（当前限 4000 字、内置 3 个，可以接受）。
- 手动挂载：用户得多点一下；换来的是行为可预测、排障简单。
- 白名单写窄会让模型无工具可用：用「显示工具数与名字 + 空=不限制」缓解。

## 何时该改

- 技能超过 ~10 个或单个正文上千字 → 做「目录 + 命中加载」；
- 用户明确嫌手动挂载麻烦 → 再评估自动选择（并同时接受多一次模型调用）。
