# ADR-0016 聊天执行状态与断流恢复

- 日期：2026-11-18
- 状态：已接受
- 延续：[ADR-0015](0015-chat-feed-projection.md)

## 背景

原聊天 Store 分别保存实时步骤、历史缓存、审批和多个布尔值；发送、审批各自维护一套收尾逻辑。创建会话前没有发送锁，查询审批失败又会返回空数组，导致重复提交窗口及错误解锁。

## 决定

每个 Execution 是步骤、预览、审批和运行状态的唯一可写来源，展示项继续由纯投影生成。旧对外字段只派生，不再作为另一份可写缓存。

服务端运行状态与客户端连接状态分离。首发和审批共用 runExecution，事件归并提取到 events.ts，持久步骤以 seq 去重。创建前锁定草稿并复用创建请求；同一次发送持有 request_id。

断流后只读历史核对。未确认终态时禁止重发，待审批时读取当前待决定项。历史/审批/步骤读取失败保留错误和已有数据，提供显式重试。审批决定响应丢失时以当前运行和审批编号核对，不把原审批仍待决定当作已成功决定。

事件回调绑定账号代次、会话实例和连接；历史和步骤读取校验版本。删除或退出时取消浏览器流读取，使迟到结果失效；不将取消本地读取表述为取消后端执行。

## 取舍

复用现有后端接口，不增加状态机依赖，不做自动工具重试或 SSE 断点续传。缺失 run_started 时没有可靠关联依据，必须提示刷新页面核对；按 request_id 精确查询需要后续后端协议支持。

会话列表、历史分页、路由和滚动仍留在原模块，避免把第三步扩展成第四步。浏览器自动验收使用模拟服务，真实模型联调独立报告。
