# 阶段 4 · 部署与跨端打包

> 本文件是一份可复用的阶段任务说明书：复制需求段落交给 AI 执行，产出物按文末要求落盘。

现在为项目设计并建设生产环境部署和跨平台桌面打包基建。

注意：目前尚未准备好实际云服务器，因此本阶段只建设通用部署能力，不连接真实服务器，不执行真实线上部署。

### 一、云服务器部署

目标：未来只需要补充服务器配置，即可完成部署。

提前建设：

1. 前后端 Dockerfile。
2. Docker Compose 配置。
3. 数据库容器配置。
4. 数据持久化 Volume。
5. 环境变量管理。
6. 开发、测试、生产环境配置隔离。
7. 数据库初始化与迁移。
8. Nginx 或其他反向代理方案。
9. HTTPS 接入预留。
10. 日志管理。
11. 服务健康检查。
12. 容器重启策略。
13. 备份与恢复方案。
14. 一键部署脚本。
15. 一键更新脚本。
16. 一键回滚方案。

### 二、服务器配置占位

所有服务器信息统一使用环境变量或配置模板。

例如：

- SERVER_HOST
- SERVER_USER
- SERVER_PORT
- SERVER_SSH_KEY
- DOMAIN
- DEPLOY_PATH

要求：

- 不填写虚构的真实地址。
- 不提交真实密钥。
- 提供 .env.example。
- 提供部署配置填写说明。
- 允许在没有服务器的情况下验证部署配置。

### 三、跨平台桌面端

最终目标是生成：

- macOS 安装包。
- Windows 安装包。
- Linux 安装包。

请先研究并确定适合当前架构的桌面技术方案。

重点分析：

1. 桌面端与 Web 前端的代码复用。
2. 桌面端与后端的通信方式。
3. 本地后端服务如何启动和关闭。
4. 桌面端如何管理本地数据。
5. 如何处理不同操作系统的文件路径和权限。
6. 如何生成不同平台的安装包。
7. 是否需要代码签名。
8. 自动更新如何实现。
9. 是否支持 CI 环境下自动构建。
10. 如何管理不同平台的构建差异。

### 四、CI/CD

预先规划：

- 代码提交检查。
- 自动化测试。
- 前后端构建。
- Docker 镜像构建。
- 镜像版本管理。
- 桌面端跨平台构建。
- 构建产物管理。
- 后续自动部署。

### 五、验收标准

在没有真实服务器的情况下，至少完成：

- Dockerfile 配置检查。
- Docker Compose 配置检查。
- 本地容器启动测试（条件允许时）。
- 环境变量检查。
- 健康检查验证。
- 部署脚本静态检查。
- 桌面端构建流程验证。
- CI 工作流语法检查。

不能把配置文件创建成功等同于部署成功。
