# 阶段 5 · 开发计划与最小可交付任务

> 本文件是一份可复用的阶段任务说明书：复制需求段落交给 AI 执行，产出物按文末要求落盘。

基于已经确定的项目架构、AI 开发规范和部署方案，制定完整的项目开发计划。

要求遵循最小可交付原则（Incremental Delivery）。

### 一、阶段划分

请至少将项目分成以下阶段：

阶段 1：AI 开发基建。

阶段 2：前后端项目骨架。

阶段 3：基础 API 和数据库。

阶段 4：LLM 接入与基础对话。

阶段 5：Agent 基础执行循环 + Tool Calling。

- 实现「模型 ↔ 工具」的往返循环：模型决定调不调工具、调几次、何时收尾。
- 工具调用用**原生结构化协议**（OpenAI `tool_calls` / Anthropic `tool_use`），不要用文本解析。
- 必须有护栏：最大步数、单工具超时、连续失败中止、上下文裁剪。
- 每一步要落库（运行 + 步骤），前端可实时看到「第几步、调了什么、结果如何」，刷新可回放。
- 工具只读、白名单、强制按当前用户隔离。

阶段 6：工具生态与权限治理（Tool Calling 深化）。

- 工具注册表：声明式注册、JSON Schema、按能力分组，新增工具不改执行器。
- 权限分级：只读 / 写入 / 外部，写入类工具必须有人工审批；保留审计日志。
- 写工具与审批流：审批挂起、超时、拒绝、放行四种结果都要有明确状态。
- 工具结果的可观测性：耗时、失败率、调用分布，支持按用户排查。
- 为阶段 7 的 MCP 接入留出适配层（工具来源可替换）。

阶段 7：Skill 和 MCP。

阶段 8：RAG 和 Memory。

阶段 9：Agent 应用功能完善。

阶段 10：桌面端集成。

阶段 11：部署、测试和发布。

阶段划分可以根据实际架构调整，不要为了凑齐阶段而引入不必要的功能。

### 二、任务拆分要求

每个阶段拆分为若干个独立任务。

任务必须足够小，最好能够在一次 AI 编程会话中完成。

每个任务必须包含：

- Task ID。
- 任务名称。
- 任务目标。
- 前置依赖。
- 涉及模块。
- 具体实施步骤。
- 预期交付文件。
- 验收标准。
- 测试方法。
- 风险和注意事项。

### 三、学习与实践结合

由于这是一个 AI 学习项目，需要区分：

1. 必须理解的核心知识。
2. 可以直接复用的成熟工具。
3. 需要亲自实现的核心机制。
4. 可以交给 AI 自动完成的工程化工作。

对于 Agent 核心机制，应结合 Hello-Agents 的学习内容安排实践。

不要求为了学习而重复实现成熟的基础设施。

### 四、进度管理

建立：

- docs/plan/ROADMAP.md
- docs/plan/TASKS.md
- docs/plan/PROGRESS.md
- docs/plan/MILESTONES.md

使用明确的状态：

- TODO
- IN_PROGRESS
- BLOCKED
- DONE

每次只允许有一个当前执行的最小任务，除非任务之间明确独立且适合并行。

### 五、任务执行规范

每完成一个任务：

1. 检查交付内容。
2. 执行测试。
3. 验证验收标准。
4. 更新任务状态。
5. 更新项目进度。
6. 记录遗留问题。
7. 给出下一任务建议。

如果任务没有通过验收，不得标记为 DONE。

### 六、最终交付

先输出完整开发路线图和任务清单，不要立即开始执行任务。

完成后等待确认。
