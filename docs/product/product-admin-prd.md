## 1. 背景与目标

### 1.1 背景与问题

`python/fastapi-demo` 已具备商品与分类的完整后端能力（共 11 个接口：商品增删改查、分页模糊搜索、商品总数统计、分类增删改查、各分类商品数统计），但**没有任何可视化界面**。当前维护数据只能依赖 curl、接口文档或直接改数据库，由此产生三个问题：

1. **录入门槛高**：非技术运营无法独立录入商品，必须找开发代操作，一条数据平均等待 0.5 天。
2. **状态不可见**：上架/下架、库存余量、分类归属散落在数据库里，主管无法快速盘点，盘点依赖临时写 SQL。
3. **分类维护易错**：分类改名/删除需要手写语句；删掉仍有商品的分类会破坏商品归属，或触发数据库外键报错而无人能解读。

因此 v1 的目标不是重写后端，而是**在现有接口之上补一层桌面端管理界面**，让运营、主管、新人三类角色可以零 SQL 完成日常维护。

### 1.2 产品目标

1. 提供单页管理后台，覆盖「看数据 → 录数据 → 改数据 → 删数据」的完整闭环，全部 8 项 P0 能力可用。
2. 前端校验与后端约束完全对齐：用户能提前看到问题，而不是提交后才收到 422；后端报错文案原样透出，用户看到「分类名称已存在」这类可行动信息，而非笼统的「操作失败」。
3. 桌面优先（≥1280px），信息密度优先，一屏内完成 90% 的日常操作。

### 1.3 成功指标

| 指标 | 口径 | 目标值 |
| --- | --- | --- |
| 单条商品录入耗时 | 从点击「新增商品」到弹出成功提示 | ≤ 30 秒 |
| 列表首屏可交互 | 本地环境（seed 后 8 条数据、每页 10 条），从进入页面到表格渲染完成 | ≤ 1 秒 |
| P0 验收通过率 | 第 8 节 15 条用例在真实链路上一次通过数 | 15/15 |
| 非法输入前端拦截率 | 空名称、价格 3 位小数、负库存、未选分类等明显非法输入 | 100% 不发请求 |
| 可行动错误文案透出率 | 4xx 业务错误中展示后端 `message` 原文的比例 | 100% |
| 分类误删率 | 因缺少二次确认导致的误删 | 0 起 |

### 1.4 范围概述

- **v1.0（P0）**：布局导航、商品列表、搜索筛选、增删改商品、分类管理、概览统计、全局状态与响应式，详见第 4 章。
- **v1.1（P1）候选**：批量下架、导出 CSV、操作日志、库存预警、上下架分布，详见第 10 章；**不做**项见第 9 章。

## 3. 信息架构

### 3.1 结构

```
商品管理网站
├─ 概览（首页，只读统计）
├─ 商品管理
│  ├─ 商品列表（默认主页面）
│  └─ 商品弹窗层：新增商品 / 编辑商品 / 删除确认
└─ 分类管理
   ├─ 分类列表
   └─ 分类弹窗层：新增分类 / 分类改名 / 删除确认
```

结构为两级：**一级导航页面**（概览、商品管理、分类管理）+ **二级弹层**（新增/编辑/确认），新增与编辑不占用独立路由，避免用户丢失列表上下文。**布局约束**：左侧固定导航 200px（三项菜单），顶部 56px 栏（页面标题 + 面包屑），内容区内边距 24px；表格行高、字号、颜色以 `docs/design/product-admin-design.md` 的 Design Token 为准。≥1280px 不出现横向滚动条；更窄视口不承诺移动端体验。

## 5. 字段与校验规则

### 5.1 接口与响应约定（对齐后端真实实现）

| 项目 | 约定 |
| --- | --- |
| 基础路径 | 前端请求 `/api`，开发期由 Vite 代理到 `http://127.0.0.1:8000` |
| 成功响应 | `{"code":200,"message":"请求成功","data":...}`，HTTP 200 |
| 失败响应 | HTTP 4xx/5xx + `{"code":<同 HTTP 状态码>,"message":"中文原因","data":null}`；**422 例外：`data` 为校验错误数组，不是 null** |
| 分页结构 | `data = {items,total,page,page_size}`，`total` 为符合筛选条件的总数 |
| 价格 / 时间 / 分类名称 | `price` 固定两位小数字符串（如 `"3.50"`），前端展示 `¥3.50`；`create_time` 为 `yyyy-MM-dd HH:mm:ss`；`category_name` 仅分页列表返回 |
| 排序规则 | 商品列表、分类列表按 ID 倒序；分类统计按 ID 升序 |

### 5.2 商品字段与校验

| 字段（中文 / 接口键） | 类型 | 必填 | 后端真实约束 | 前端预校验文案 | 后端报错（状态码 / 文案） |
| --- | --- | --- | --- | --- | --- |
| 商品名称 / `name` | string | 是 | 1–50 个字符；去首尾空白后不能为空 | 「请输入商品名称」「商品名称不能超过 50 个字符」 | 400「商品名称不能只包含空白」；超长 422「请求参数校验失败」 |
| 所属分类 / `category_id` | int | 是 | 正整数（>0），且必须存在于分类表 | 「请选择所属分类」 | 400「商品分类不存在」；非正整数 422「请求参数校验失败」 |
| 价格 / `price` | decimal | 是 | ≥0；最多 2 位小数；最多 8 位有效数字，即最大 999999.99 | 「请输入价格」「价格最多 2 位小数」「价格不能小于 0」 | 422「请求参数校验失败」 |
| 库存 / `stock` | int | 否（默认 0） | ≥0 的整数，无上限；v1 表单设为必填 | 「请输入库存」「库存必须为不小于 0 的整数」 | 422「请求参数校验失败」 |
| 上架状态 / `shelf_status` | boolean | 否（默认 true） | true=上架，false=下架 | 开关默认「上架」 | 非布尔值 422「请求参数校验失败」 |
| 商品 ID / `id`、创建时间 / `create_time`、分类名称 / `category_name` | int / string / string | 只读 | `id` 自增主键；`create_time` 由服务端生成；`category_name` 仅分页列表返回 | — | 路径参数非正整数 422；字段本身不可写 |

### 5.3 分类字段与校验

| 字段（中文 / 接口键） | 类型 | 必填 | 后端真实约束 | 前端预校验文案 | 后端报错（状态码 / 文案） |
| --- | --- | --- | --- | --- | --- |
| 分类名称 / `name` | string | 是 | 1–50 个字符；创建时去首尾空白后不能为空；全库唯一（数据库唯一索引） | 「请输入分类名称」「分类名称不能超过 50 个字符」「分类名称已存在」 | 400「分类名称不能只包含空」；409「分类名称已存在」 |
| 分类 ID / `id`、创建时间 / `create_time` | int / string | 只读 | 自增主键；`create_time` 格式 `yyyy-MM-dd HH:mm:ss` | — | 路径参数非正整数 422 |
| 商品数 / `product_count` | int | 只读 | 由分类统计接口提供，含 0 | — | — |

### 5.4 接口清单（v1 依赖，路径不可改）

| 编号 | 方法 与 路径 | 用途 | 关键参数 | 成功 `data` |
| --- | --- | --- | --- | --- |
| A-01 | GET `/api/products` | 分页模糊查询 | `keyword`（≤50 字符）、`category_id`（>0）、`page`（≥1，默认 1）、`page_size`（1–100，默认 10） | `{items,total,page,page_size}`，items 含 `category_name` |
| A-02 | GET `/api/products/count` | 商品总数（不受筛选影响） | 无 | `{total}` |
| A-03 | GET `/api/products/{product_id}` | 商品详情 | 路径 `product_id`（>0） | 单个商品（**不含** `category_name`） |
| A-04 | POST `/api/products` | 新增商品 | 见 5.2 字段表 | 新商品（`price` 字符串、`create_time`） |
| A-05 | PATCH `/api/products/{product_id}` | 局部修改 | 同 5.2，字段可省略；至少一个字段；显式 `null` 会被拒绝 | 修改后商品 |
| A-06 | DELETE `/api/products/{product_id}` | 删除商品 | 路径 `product_id` | `null` |
| A-07 | GET `/api/categories` | 分类列表 | 无 | `[{id,name,create_time}]`，ID 倒序 |
| A-08 | POST `/api/categories` | 新增分类 | `{name}` | 新分类 |
| A-09 | PATCH `/api/categories/{category_id}` | 分类改名 | `{name}` | 修改后分类 |
| A-10 | DELETE `/api/categories/{category_id}` | 删除分类 | 路径 `category_id` | `null` |
| A-11 | GET `/api/categories/statistics` | 各分类商品数 | 无 | `[{id,name,product_count}]`，含 0，ID 升序 |

### 5.5 错误码语义

| 状态码 | 含义 | 典型文案 |
| --- | --- | --- |
| 400 | 业务校验失败（可行动） | 商品名称不能只包含空白 / 商品分类不存在 / 分类名称不能只包含空 / 至少提交一个需要修改的字段 / 字段 {name} 的值不允许为 null |
| 404 | 资源不存在 | 商品不存在（详情、删除）/ 未找到商品（修改）/ 分类不存在 / 路由不存在时为 `Not Found` |
| 409 | 唯一性冲突或删除被拒绝 | 分类名称已存在 / 分类下有其他商品，不能删除分类 |
| 422 | 请求参数校验失败 | 请求参数校验失败（字段级明细在 `data` 数组中，为英文） |
| 500 | 服务端异常 | 数据库操作失败，请检查记录后重试 / 服务器内部错误 |

### 5.6 校验与提示规则

1. **前端先校验、后端兜底**：明显非法输入（空名称、价格 3 位小数、负库存、未选分类）在前端拦截，不发送请求；后端 422 只作为兜底。
2. **后端 message 优先**：400/404/409 原样展示后端文案，不改写、不吞掉。
3. **422 不展示英文明细**：统一提示「提交内容不符合要求，请检查后再试」。
4. **价格只读字符串**：展示直接用后端字符串；编辑回填时按字符串转数字展示，保存时提交数字或两位小数字符串。
5. **字符长度按字符计**：名称最多 50 个字符（中文按 1 个字符计），与后端 `min_length/max_length` 一致。
6. **删除必须二次确认**，确认文案必须包含「删除后不可恢复」。

| --- | --- | --- | --- |
| 1 | 进入「商品管理」 | A-01（page=1、page_size=10）+ A-02 + A-07 | 表格 loading；统计条显示商品总数、分类数、当前筛选结果数 |
| 2 | 输入关键词后回车或点「查询」 | A-01（带 `keyword`，page 重置为 1） | 表格刷新，分页回第 1 页，total 为匹配数 |
| 3 | 选择分类 | A-01（带 `category_id`，page 重置为 1） | 与关键词组合生效；下拉保留选中项 |
| 4 | 切换每页条数（10/20/50）或点击页码 | A-01（page 重置为 1 或保持筛选翻页） | 表格刷新，页码高亮同步，筛选条件保留 |
| 5 | 点「重置」 | A-01（无筛选、page=1） | 关键词清空、分类回「全部分类」、分页回第 1 页 |
| 6 | 搜索结果为 0 | 同步骤 2 | 表格区展示空态「没有符合条件的商品」+「清空筛选」按钮 |
| 7 | 新增/编辑成功后 | A-01 | 新增回第 1 页；编辑保持当前页与筛选 |

### 6.2 新增商品（L-01）

1. 点「新增商品」→ 弹窗打开，字段为空，上架开关默认开启。
2. 所属分类下拉数据来自 A-07；无分类时提示「还没有分类，请先到分类管理创建」并禁用保存。
3. 用户填写名称、分类、价格、库存；名称/价格/库存失去焦点即校验，错误文案显示在字段下方（红色 12px）。
4. 点「保存」→ 前端整体校验；不通过则聚焦首个错误字段、不发请求。
5. 校验通过 → 按钮变为「保存中…」且禁用，弹窗关闭按钮同时禁用，防止重复提交。
6. 成功 → 弹窗关闭并清空、提示「新增成功」、列表回第 1 页刷新、统计条更新（商品总数 +1）。
7. 失败 → 弹窗保留、已填内容不丢、按钮恢复可点、提示区展示后端 message。

### 6.3 编辑商品（L-02）

1. 点行内「编辑」→ 弹窗回填该行：名称、分类、价格（两位小数）、库存、上架开关；ID 与创建时间只读展示。
2. 点「取消」或关闭弹窗 → 不发送任何请求，列表数据保持原样（不脏写）。
3. 修改后保存 → 仅提交发生变化的字段（PATCH 局部更新）；若用户未改动任何字段，提示「未修改任何内容」并关闭弹窗，不发请求。
4. 成功 → 提示「保存成功」、弹窗关闭、**保持当前页码与筛选条件**刷新当前页，该行显示新值。
5. 失败 → 弹窗保留并提示后端 message（如「商品分类不存在」「未找到商品」）。

### 6.4 删除商品（L-03）

1. 点行内「删除」→ 二次确认弹窗：标题「删除商品」，正文「确定删除商品「{商品名}」吗？删除后不可恢复。」
2. 点「取消」→ 关闭弹窗、不发请求；点「确认删除」→ 按钮变「删除中…」并禁用，成功后提示「删除成功」并刷新当前页。
3. 若删除后当前页为空且当前页码 >1 → 自动回到上一页并加载；若已是第 1 页则展示空态。
4. 失败（如商品已被他人删除，404）→ 提示后端 message，并刷新当前页使数据回到真实状态。

### 6.5 分类管理（P-03）

1. 进入页面 → 同时请求 A-07（分类列表）与 A-11（各分类商品数），按分类 ID 合并出「商品数」列；请求失败则商品数列显示「—」。
2. 新增分类：点「新增分类」→ 弹窗输入名称 → 保存成功提示「新增成功」，列表与统计刷新。
3. 分类改名：行内「改名」→ 弹窗回填旧名 → 保存成功提示「保存成功」，列表刷新，商品列表的分类下拉在下次进入时同步为新名。
4. 删除分类：行内「删除」→ 确认弹窗，正文「确定删除分类「{分类名}」吗？删除后不可恢复。分类下仍有商品时无法删除。」
5. 删除有商品的分类 → 后端 409，**原样提示「分类下有其他商品，不能删除分类」**，弹窗关闭、列表刷新；删除空分类 → 提示「删除成功」并刷新。
7. 分类重名（新增或改名）→ 后端 409，原样提示「分类名称已存在」，弹窗保留供修改。

### 6.6 概览（P-01）

1. 进入页面 → 请求 A-02（商品总数）、A-07（分类数）、A-11（各分类商品数）。
2. 顶部两个数字卡：商品总数、分类数；下方按分类展示名称 + 商品数（条形长度按最大商品数等比），商品数为 0 的分类也展示。
3. 商品总数与分类数均为 0 时展示空态「暂无统计数据」，并提供「去新增商品」入口。
4. 请求失败 → 数字显示「—」，提示后端 message；不阻塞其他区域。

## 7. 文案与状态

### 7.1 空态

| 场景 | 主文案 | 辅助说明 | 操作按钮 |
| --- | --- | --- | --- |
| 商品列表无任何商品 | 还没有商品 | 点击右上角「新增商品」录入第一件商品 | 新增商品 |
| 搜索/筛选无结果 | 没有符合条件的商品 | 尝试更换关键词，或清空筛选条件 | 清空筛选 |
| 分类列表无分类 | 还没有分类 | 先创建一个分类，再录入商品 | 新增分类 |
| 概览无数据 | 暂无统计数据 | 商品与分类都为空 | 去新增商品 |

### 7.2 加载态

| 场景 | 表现 |
| --- | --- |
| 表格加载 / 搜索 / 翻页 / 切换每页条数 | 表格区域 loading 遮罩，不出现空白闪烁；「查询」按钮同时 loading，重复点击不重复发请求 |
| 新增/编辑保存中 | 主按钮文案「保存中…」且禁用，弹窗不可关闭 |
| 删除请求中 | 「确认删除」按钮文案「删除中…」且禁用 |
| 概览首次加载 | 数字占位显示「—」，返回后替换 |

### 7.3 错误态

| 场景 | 判定 | 提示方式与文案 |
| --- | --- | --- |
| 网络异常 / 后端未启动 | 请求无响应、连接被拒绝 | 提示「网络异常，请确认后端已启动」；列表保留上次数据 |
| 4xx 业务错误 | `code=400/404/409` | 原样展示后端 `message`：商品分类不存在 / 商品不存在 / 分类名称已存在 / 分类下有其他商品，不能删除分类；404 后刷新列表 |
| 422 参数校验失败 | `code=422` | 统一提示「提交内容不符合要求，请检查后再试」，不展示英文明细 |
| 5xx 服务端异常 | `code>=500` | 「服务器内部错误，请稍后重试」，并提供刷新入口 |

### 7.4 按钮与禁用规则

| 控件 | 规则 |
| --- | --- |
| 保存（新增/编辑） | 提交中禁用；必填项为空时仍可点击，点击后逐项标红（避免用户不知为何按钮不可用）；分类下拉为空时禁用保存并提示先创建分类 |
| 确认删除 | 请求中禁用；同一行操作未完成前不可再次触发 |
| 查询 / 重置 / 分页 / 每页条数 | 请求中禁用重复触发 |
| 行内「编辑 / 删除」 | 该行请求进行中时禁用该行按钮 |

### 7.5 文案规范

- 全角中文标点；按钮与提示使用动宾结构（「新增商品」「保存」「删除成功」）；表单必填项标红星 `*`，错误提示显示在字段下方，不使用悬浮提示。
- 金额统一 `¥` + 两位小数（`¥3.50`）；库存为纯整数；状态为「上架」（绿色标签）/「下架」（灰色标签）。
- 时间统一 `yyyy-MM-dd HH:mm:ss`；空值显示「—」而非空白。
