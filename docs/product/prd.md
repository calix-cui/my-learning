# 「简易商品管理网站」产品需求文档（PRD v1.1）

> 本文给人读。接口细节以 python/fastapi-demo/docs/api.md 为准，视觉规范见 docs/design/design.md。

## 1. 目标与范围

`python/fastapi-demo` 已具备商品与分类的完整后端能力（11 个接口：商品增删改查、分页模糊搜索、商品总数统计、分类增删改查、各分类商品数统计），但没有任何可视化界面。维护数据只能靠 curl、接口文档或直接改库：运营录一条商品要等开发半天，主管盘点上架状态只能临时写 SQL，新人删分类常撞上外键报错。v1 不重写后端，只在现有接口上补一层桌面端管理界面，让运营、主管、新人三类角色零 SQL 完成日常维护。

| 指标 | 口径 | 目标值 |
| --- | --- | --- |
| 单条商品录入耗时 | 点击「新增商品」到弹出成功提示 | ≤ 30 秒 |
| 列表首屏可交互 | seed 数据、每页 10 条，进入页面到表格渲染完成 | ≤ 1 秒 |
| 非法输入前端拦截率 | 空名称、价格 3 位小数、负库存、未选分类 | 100% 不发请求 |
| P0 验收通过率 | 第 7 节 15 条用例在真实链路一次通过 | 15/15 |

- **v1.0（P0，本次交付）**：布局导航、商品列表 / 搜索 / 筛选 / 分页、商品增删改、分类管理、概览统计、全局状态与桌面布局，即 F-01 至 F-16。
- **v1.1（P1，候选）**：批量下架、导出 CSV、操作日志、库存预警、上下架分布，即 F-17 至 F-21；不做项见第 8 节。

## 2. 用户与前提

| 角色 | 职责 | 使用频率 | 核心诉求 |
| --- | --- | --- | --- |
| 运营专员 | 录入新品、调价、改库存、上下架 | 每天多次 | 录入快、少填错、改完立刻看到结果 |
| 店铺主管 | 盘点库存与上架状态、核对分类结构 | 每周 1–2 次 | 一眼看到全量与分类分布，能筛选定位 |
| 新入职运营 | 维护分类、整理历史数据 | 每周 1 次 | 不需要 SQL 知识，误操作有拦截 |

使用前提：MySQL `fastapi_demo` 库可用，后端在 `http://127.0.0.1:8000` 启动，前端 5173 端口并代理 `/api`。`python -m app.seed` 写入 3 个分类、12 个商品（每个分类 4 个，含 2 个下架商品，价格含 `3.50`）；若库中已有历史数据会更多，验收时以列表 `total` 的实际值为准。

## 3. 信息架构与页面

结构为两级：三个一级页面（概览、商品管理、分类管理）+ 六个二级弹层（新增 / 编辑 / 删除确认，商品与分类各三个）；新增与编辑不占独立路由，避免丢失列表上下文。布局：左侧固定导航 200px，顶部 56px 栏（页面标题 + 面包屑），内容区内边距 24px；≥1280px 不出现横向滚动条，更窄视口不承诺移动端体验。

| 编号 | 层级 | 页面 / 弹层 | 入口 | 主要内容 |
| --- | --- | --- | --- | --- |
| P-01 | 一级 | 概览 | 左侧导航「概览」 | 商品总数、分类数、各分类商品数（条形 / 卡片） |
| P-02 | 一级 | 商品管理 | 左侧导航「商品管理」、站点默认页 | 统计条 + 搜索区 + 商品表格 + 分页 |
| P-03 | 一级 | 分类管理 | 左侧导航「分类管理」 | 分类表格（含商品数列）+ 新增按钮 |
| L-01/L-02 | 二级 | 新增 / 编辑商品弹窗 | 商品页「新增商品」、行内「编辑」 | 名称、分类、价格、库存、上架开关；编辑回填当前行，ID 与创建时间只读 |
| L-03 | 二级 | 删除商品确认 | 商品行「删除」 | 二次确认，说明不可恢复 |
| L-04/L-05 | 二级 | 新增分类 / 分类改名弹窗 | 分类页「新增分类」、行内「改名」 | 分类名称；改名回填旧名 |
| L-06 | 二级 | 删除分类确认 | 分类行「删除」 | 二次确认，说明有商品时无法删除 |

## 5. 字段、接口与错误码

| 字段（商品 + 分类合并；中文 / 接口键） | 类型 | 必填 | 后端真实约束 | 前端预校验文案 | 后端报错（状态码 / 文案） |
| --- | --- | --- | --- | --- | --- |
| 商品名称 / `name` | string | 是 | 1–50 字符；去首尾空白后非空 | 请输入商品名称 / 商品名称不能超过 50 个字符 | 400「商品名称不能只包含空白」；超长 422「请求参数校验失败」 |
| 所属分类 / `category_id` | int | 是 | 正整数且必须存在于分类表 | 请选择所属分类 | 400「商品分类不存在」；非正整数 422 |
| 价格 / `price` | decimal | 是 | ≥0；最多 2 位小数；最多 8 位有效数字（最大 999999.99） | 请输入价格 / 价格最多 2 位小数 / 价格不能小于 0 | 422「请求参数校验失败」 |
| 库存 / `stock` | int | 否（默认 0，表单必填） | ≥0 的整数，无上限 | 请输入库存 / 库存必须为不小于 0 的整数 | 422「请求参数校验失败」 |
| 上架状态 / `shelf_status` | boolean | 否（默认 true） | true=上架，false=下架 | 开关默认「上架」 | 非布尔值 422 |
| 商品 ID / `id`、创建时间 / `create_time`、分类名称 / `category_name` | int / string / string | 只读 | 自增主键；服务端生成；`category_name` 仅分页列表返回 | — | 路径参数非正整数 422 |
| 分类名称 / `name` | string | 是 | 1–50 字符；新增与改名都去首尾空白后非空；全库唯一 | 请输入分类名称 / 不能超过 50 个字符 / 分类名称已存在 | 400「分类名称不能只包含空」；409「分类名称已存在」 |
| 分类 ID / `id`、创建时间 / `create_time`、商品数 / `product_count` | int / string / int | 只读 | 自增主键；`yyyy-MM-dd HH:mm:ss`；`product_count` 由统计接口提供，含 0 | — | 路径参数非正整数 422 |

| 编号（接口清单，路径不可改，参数以 `docs/api.md` 为准） | 方法 与 路径 | 用途 |
| --- | --- | --- |
| A-01 | GET `/api/products` | 分页模糊查询（keyword / category_id / page / page_size） |
| A-02 | GET `/api/products/count` | 商品总数，不受筛选影响 |
| A-03 | GET `/api/products/{product_id}` | 商品详情（不含 category_name） |
| A-04 | POST `/api/products` | 新增商品 |
| A-05 | PATCH `/api/products/{product_id}` | 局部修改，至少一个字段，显式 null 被拒 |
| A-06 | DELETE `/api/products/{product_id}` | 删除商品 |
| A-07 | GET `/api/categories` | 分类列表，ID 倒序 |
| A-08 | POST `/api/categories` | 新增分类 |
| A-09 | PATCH `/api/categories/{category_id}` | 分类改名 |
| A-10 | DELETE `/api/categories/{category_id}` | 删除分类 |
| A-11 | GET `/api/categories/statistics` | 各分类商品数，含 0，ID 升序 |

| 状态码（错误码语义） | 含义 | 典型文案 |
| --- | --- | --- |
| 400 | 业务校验失败（可行动） | 商品名称不能只包含空白 / 商品分类不存在 / 分类名称不能只包含空 / 至少提交一个需要修改的字段 / 字段 {name} 的值不允许为 null |
| 404 | 资源不存在 | 商品不存在（详情、删除）/ 未找到商品（修改）/ 分类不存在 / 路由不存在为 `Not Found` |
| 409 | 唯一性冲突或删除被拒 | 分类名称已存在 / 分类下有其他商品，不能删除分类 |
| 422 | 参数校验失败 | 请求参数校验失败（字段级明细在 `data` 数组中，为英文） |
| 500 | 服务端异常 | 数据库操作失败，请检查记录后重试 / 服务器内部错误 |

**校验与提示规则**

1. 前端先校验、后端兜底：明显非法输入（空名称、价格 3 位小数、负库存、未选分类）不发送请求，422 仅兜底。
2. 后端 message 优先：400 / 404 / 409 原样展示后端文案，不改写、不吞掉。
3. 422 不展示英文明细，统一提示「提交内容不符合要求，请检查后再试」。
4. 价格按字符串处理：展示直接用后端两位小数字符串；编辑回填转数字展示，保存提交数字或两位小数字符串。
5. 名称长度按字符计（中文按 1 个字符），最多 50 字符，与后端 min_length / max_length 一致。
6. 删除必须二次确认，确认文案必须包含「删除后不可恢复」。

| 场景（空态与加载态） | 文案与表现 |
| --- | --- |
| 商品列表 / 分类列表 / 概览为空 | 分别显示「还没有商品」（附「新增商品」）、「还没有分类」（附「新增分类」）、「暂无统计数据」（附「去新增商品」） |
| 搜索 / 筛选无结果 | 「没有符合条件的商品」，附「清空筛选」入口 |
| 表格加载 / 搜索 / 翻页 / 切每页 | 表格 loading 遮罩，不空白闪烁；「查询」按钮同时 loading，重复点击不重复发请求 |
| 保存 / 删除请求中 | 主按钮文案「保存中…」/「删除中…」并禁用，弹窗不可关闭（同时禁用对应按钮防重复提交） |

| 场景（错误态） | 提示方式与文案 |
| --- | --- |
| 网络异常 / 后端未启动 | 「网络异常，请确认后端已启动」；列表保留上次数据 |
| 4xx 业务错误（400 / 404 / 409） | 原样展示后端 `message`；404 后刷新列表 |
| 422 参数校验失败 | 统一提示「提交内容不符合要求，请检查后再试」，不展示英文明细 |
| 5xx 服务端异常 | 「服务器内部错误，请稍后重试」，并提供刷新入口 |

## 6. 交互要点

- 商品列表：进入时请求 A-01（page=1、page_size=10）+ A-02 + A-07；关键词或分类变更后页码重置为 1；翻页与切换每页保留筛选；「重置」清空筛选回第 1 页；无结果展示空态 +「清空筛选」。请求进行中禁用对应按钮（查询 / 重置 / 分页 / 行内编辑删除），同一行操作未完成前不可重复触发。
- 新增商品：分类下拉来自 A-07，无分类时禁用保存并提示先创建分类；名称 / 价格 / 库存失焦即校验，错误文案显示在字段下方；保存中按钮禁用、弹窗不可关闭；成功 toast「新增成功」并回第 1 页刷新；失败弹窗保留、已填内容不丢、原样展示后端 message。
- 编辑商品：回填当前行，ID 与创建时间只读；点「取消」不发请求（不脏写）；仅提交改动字段（PATCH），未改动时提示「未修改任何内容」且不发请求；成功保持当前页码与筛选刷新当前页；失败保留弹窗并提示原文。
- 删除商品：确认弹窗正文含商品名并说明「删除后不可恢复」；确认中按钮禁用；删除后当前页为空且页码 >1 自动回上一页，否则展示空态；404 时提示原文并刷新列表使数据回到真实状态。
- 分类管理：进入时合并 A-07 与 A-11 计算「商品数」列，A-11 失败则该列显示「—」；新增 / 改名成功 toast 并刷新；重名 409 原样提示「分类名称已存在」且弹窗保留；删除有商品的分类 409 原样提示「分类下有其他商品，不能删除分类」，删除空分类成功。
- 概览：请求 A-02、A-07、A-11；顶部两个数字卡 + 分类商品数条形（商品数为 0 也展示）；全空时展示「暂无统计数据」；请求失败数字显示「—」且不阻塞其他区域。

## 7. 验收标准

**前置条件**：MySQL `fastapi_demo` 可用；后端 8000 启动；`python -m app.seed` 已执行（3 个分类：饮料、零食、乳品；seed 写入 12 个商品，含 2 个下架商品，价格含 `3.50`）；前端 5173 启动且 `/api` 代理正常；浏览器宽度 1440px。

> 下文的 **N** 指「当前库中商品总数」= `GET /api/products/count` 的返回值。本机干净库 seed 后 N=12；若库中已有历史数据则 N 更大（例如 14），验收以实际值为准，不写死数字。

| 编号 | Given（前置） | When（操作） | Then（期望） |
| --- | --- | --- | --- |
| AC-01 | 库中商品总数 N | 打开「商品管理」 | 表格 N 行，按 ID 倒序；列为 ID/名称/分类/价格/库存/状态/创建时间/操作；价格显示 `¥3.50` 且右对齐；下架商品状态为灰色标签 |
| AC-02 | 商品总数 N ≥ 11 | 每页设 10 条，进入第 2 页 | 第 1 页 10 行、第 2 页 N−10 行；分页 total=N；第 2 页不再显示第 1 页数据 |
| AC-03 | 存在名称含「可乐」的商品 | 关键词输入「可乐」并回车 | 仅显示名称含「可乐」的商品，total 等于匹配数，页码回到第 1 页，筛选条件保留在输入框 |
| AC-04 | 存在分类「零食」且其下有商品 | 分类下拉选「零食」 | 仅显示该分类商品；再叠加关键词后结果为两者交集；总数随之变化 |
| AC-05 | 任意数据 | 关键词输入「不存在的商品XYZ」 | 表格区显示「没有符合条件的商品」与「清空筛选」按钮；点击后恢复全部数据且页码为 1 |
| AC-06 | 存在分类「饮料」 | 点「新增商品」，填名称「测试商品A」、分类「饮料」、价格 `3.5`、库存 `10`、上架，保存 | 弹窗关闭并提示「商品新增成功」；列表回第 1 页且首行为「测试商品A」，价格显示 `¥3.50`，状态「上架」；统计条商品总数 +1 |
| AC-07 | 打开新增弹窗 | 名称留空直接保存；再将价格填为 `3.555` | 名称下方提示「请输入商品名称」且不发请求；价格下方提示「价格最多 2 位小数」且不发请求；网络面板无新增请求 |
| AC-08 | 第 1 页存在库存 10 的商品 | 点该行「编辑」，库存改为 `99`，保存 | 提交弹窗内全部可编辑字段（名称/分类/价格/库存/状态，PATCH 一次）；提示「商品修改成功」；弹窗关闭后仍停留第 1 页，该行库存显示 99，其他行不变 |
| AC-09 | 任意商品行 | 点「删除」后确认弹窗点「取消」；再点「删除」并确认 | 取消时无请求、数据不变；确认后提示「删除成功」，该行消失、total 减 1 |
| AC-10 | 商品总数 N、每页 10 条、当前第 2 页 | 依次删除第 2 页的全部商品 | 删完最后一条后自动回到第 1 页并加载数据，不出现空白页或「第 2 页 / 共 1 页」矛盾 |
| AC-11 | 已有分类「饮料」 | 新增分类「测试分类」；将其改名为「测试分类2」；再新增名为「饮料」的分类 | 新增后列表出现「测试分类」（商品数 0）；改名后行显示「测试分类2」；重名时提示「分类名称已存在」且弹窗保留 |
| AC-12 | 「零食」分类下有商品、存在一个空分类 | 分别删除「零食」与空分类 | 删除「零食」提示「分类下有其他商品，不能删除分类」且分类仍在；删除空分类提示「删除成功」且从列表消失 |
| AC-13 | seed 数据 | 打开「概览」 | 商品总数等于 `GET /api/products/count` 的 `total`（本机 N=12）；分类数为 3；各分类商品数之和为 N，无商品分类显示 0 |
| AC-14 | 前端已加载，随后停止后端进程 | 点「查询」；恢复后端后触发一次 409（重名分类） | 停后端时提示「网络异常，请确认后端已启动」；409 时提示「分类名称已存在」；两次均无英文技术文案、无页面崩溃 |
| AC-15 | 浏览器宽度 1280px | 依次访问三个页面，并在商品列表触发一次加载 | 三页均无横向滚动条；侧边栏与顶部栏固定；加载期间表格有 loading 遮罩、按钮不可重复点击 |
