## 阅读顺序建议

1. 先看 PRD 第 1–3 节，明确目标、角色与页面范围；
2. 开发前看第 4–5 节，功能清单与字段/接口约定是唯一实现依据；
3. 联调与提测看第 6–7 节（交互流程与文案状态），测试直接用第 8 节 15 条验收标准；
4. 排期与遗留事项看第 9–11 节（非目标、版本规划、待确认问题）。

## 维护约定

- **以真实代码为准**：PRD 中字段长度、取值范围、价格格式、错误文案均来自 `python/fastapi-demo` 当前实现；后端契约变更时，须先改 PRD 第 5 节与 API 契约，再同步前端。
- **P1 不进入 v1 范围**：第 4 节标 P1 / v1.1 的功能仅为候选，本次交付与验收只对 P0（F-01 至 F-16）负责。
- **待确认问题集中管理**：第 11 节 Q-01 至 Q-07 涉及后端补接口或不一致行为，由 Leader 决策后再转交后端，产品侧不擅自承诺接口改动。
- **文案以 PRD 为准**：前端提示语、空态、按钮文案直接引用第 7 节；修改文案需同步本文档，避免与验收用例冲突。
