你现在接手一个长期迭代的 AI Agent 应用开发项目。

请先不要编写或修改任何代码。

本阶段的唯一目标是：全面了解项目现状，为后续 AI 开发基建和项目架构设计提供依据。

### 一、检查项目环境

请检查：

1. 当前 Git 仓库的目录结构。
2. 已有前端、后端、测试和文档。
3. 当前使用的技术栈及版本。
4. 已有依赖、构建工具和开发脚本。
5. 当前 Git 分支、工作区状态和提交历史。
6. 已有 Docker、CI/CD、部署脚本和环境配置。
7. 是否存在重复、过时或未使用的文件。

### 二、检查 AI 开发环境

重点检查：

1. 当前 AI 编程工具支持哪些项目规则文件。
2. 已安装的 Skills。
3. 已配置的 MCP Server。
4. 已安装的 CLI 工具。
5. 当前项目中已有的 Agent、Prompt、Rules 和 Workflow。
6. 是否存在可以复用的 AI 开发工作流。
7. 是否有值得引入的官方 Skill 或成熟工具。

不要仅根据文件名判断 Skill 的能力，必要时阅读其完整说明。

### 三、技术调研原则

对于发现的缺失能力：

- 先检查现有工具是否已经能够完成。
- 再寻找官方解决方案。
- 再比较成熟开源方案。
- 最后才提出自行实现的建议。

对外部工具的推荐必须提供：
- 官方仓库或文档。
- 核心用途。
- 适用场景。
- 维护状态。
- 是否值得当前项目引入。

### 四、交付文档

请输出以下调研报告：

1. docs/project/PROJECT_OVERVIEW.md
   - 项目现状。
   - 技术栈。
   - 目录结构。
   - 已有能力。

2. docs/project/AI_ENVIRONMENT_AUDIT.md
   - 已安装 Skill。
   - 已配置 MCP。
   - 已有 CLI。
   - 可复用能力。
   - 缺失能力。

3. docs/project/TECHNICAL_DEBT.md
   - 当前问题。
   - 潜在风险。
   - 优化建议。

4. docs/project/REUSE_CANDIDATES.md
   - 值得复用的工具。
   - 推荐引入的开源项目。
   - 可替代的重复实现。
   - 不建议引入的工具及原因。

### 五、执行限制

- 不修改现有代码。
- 不安装依赖。
- 不删除文件。
- 不擅自改变项目结构。
- 不执行有破坏性的命令。

完成后汇报调研结果，并列出最值得优先处理的五项工作。
