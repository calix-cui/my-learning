现在对当前项目进行一次全面的代码审查和阶段验收。

本次审查的目标不是追求代码数量，而是确保项目架构合理、代码质量可靠、功能真实可用。

### 一、架构审查

检查：

- 是否符合已经确定的系统架构。
- 模块职责是否清晰。
- 是否存在不必要的耦合。
- 前后端边界是否合理。
- 是否存在重复实现。
- 是否存在过度设计。
- 是否为未来 Agent 能力扩展保留合理接口。

### 二、代码质量审查

检查：

- 代码规范。
- 类型安全。
- 异常处理。
- 日志记录。
- 资源释放。
- 并发安全。
- 安全性。
- 性能问题。
- 可维护性。

### 三、依赖审查

检查：

- 是否引入重复依赖。
- 是否存在不必要的第三方库。
- 是否存在安全漏洞。
- 是否使用了已经废弃的 API。
- 是否可以使用现有工具替代自定义实现。

### 四、测试审查

检查：

- 单元测试。
- 集成测试。
- API 测试。
- 前后端联调。
- 核心业务流程。
- 异常场景。
- 部署和构建流程。

### 五、文档审查

检查文档是否与当前代码一致。

特别检查：

- 架构文档。
- API 文档。
- 环境配置。
- 开发指南。
- 部署指南。
- 任务进度。

### 六、问题分级

将发现的问题分为：

- P0：阻断性问题，必须立即修复。
- P1：严重问题，当前阶段必须解决。
- P2：一般问题，可以安排后续处理。
- P3：优化建议。

### 七、最终交付

生成审查报告：

docs/reviews/REVIEW_REPORT.md

报告必须包含：

1. 审查范围。
2. 审查结果。
3. 问题清单。
4. 风险分析。
5. 修复建议。
6. 阶段验收结论。

不要为了让审查报告看起来良好而隐瞒问题。

本次默认只审查，不直接修改代码。需要修复时，先列出修复任务并等待确认。
