基于已经完成的项目调研报告，现在开始设计和建设 AI Agent 项目的开发基建。

本阶段不开发具体业务功能，目标是建立一套高效、可维护、可扩展的 AI 辅助开发体系。

### 一、Skill 体系

建立项目级 Skill 管理机制。

要求：

1. 优先使用当前 AI 编程工具已有的 Skill。
2. 优先寻找官方和成熟社区 Skill。
3. 避免重复安装功能相近的 Skill。
4. 明确哪些 Skill 是项目级共享能力，哪些是个人开发环境能力。
5. 明确 Skill 的安装、更新、使用和维护方式。
6. 记录 Skill 的来源、版本、用途和适用范围。

重点关注以下能力：

- 前端开发。
- 后端开发。
- Python 开发。
- API 设计。
- 数据库设计。
- 自动化测试。
- Docker。
- CI/CD。
- 代码审查。
- 文档编写。
- 安全检查。
- Agent 开发。

不要为了覆盖所有类别而盲目安装 Skill。

### 二、项目规则体系

建立统一的 AI 项目规则。

需要考虑：

- 全局开发规范。
- 前端开发规范。
- 后端开发规范。
- API 规范。
- 数据库规范。
- 测试规范。
- Git 提交规范。
- 文档规范。
- 安全规范。
- 部署规范。

规则应当短小、明确、可执行。

避免将大量重复规则复制到多个文件中。

### 三、AI 工作流

建立可复用的开发工作流：

1. 需求分析。
2. 技术调研。
3. 架构设计。
4. 任务拆解。
5. 代码实施。
6. 自动化测试。
7. 代码审查。
8. 文档更新。
9. 交付汇报。

每个工作流应明确输入、输出、执行条件和验收标准。

### 四、工具链整合

检查是否需要引入：

- Git Hooks。
- Linter。
- Formatter。
- Type Checker。
- 自动化测试工具。
- API 文档工具。
- 数据库迁移工具。
- 依赖漏洞扫描。
- Docker 工具。
- CI/CD 工具。

优先复用已有工具，不要引入重复功能。

### 五、交付结果

请先设计，再分任务实施。

最终需要交付：

1. AI 开发基建架构图。
2. Skill 管理规范。
3. 项目 Rules 体系。
4. AI Workflow 体系。
5. 工具链清单。
6. 项目目录结构。
7. 初始化和维护说明。
8. 基建验收报告。

每次只实施一个最小任务。

每个任务完成后，执行验证并汇报结果，等待确认后再继续。

不要一次性完成全部建设工作。
