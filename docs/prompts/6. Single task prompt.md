### 一、执行前检查

1. 阅读项目全局规则。
2. 阅读相关架构文档。
3. 检查当前 Git 状态。
4. 检查相关代码和已有实现。
5. 检查可用 Skill、MCP 和现有工具。
6. 确认是否存在可直接复用的能力。

如果发现现有架构与任务要求冲突，先暂停并说明。

### 二、实施要求

- 严格限定任务范围。
- 不顺手开发其他功能。
- 不进行无关重构。
- 优先复用现有依赖。
- 不随意增加新的第三方依赖。
- 保持代码简洁。
- 必要时补充测试。
- 必要时更新文档。

如果遇到超出任务范围的问题，记录下来，不要擅自扩大任务范围。

### 三、验收要求

完成后必须：

1. 执行相关测试。
2. 执行代码格式检查。
3. 执行类型检查（适用时）。
4. 验证功能实际运行情况。
5. 对照任务验收标准逐项检查。

不能仅根据代码没有报错就认定任务完成。

### 四、交付汇报

按照以下格式汇报：

**任务状态：**
DONE / BLOCKED / IN_PROGRESS

**完成内容：**
说明实际实现的功能。

**文件变更：**
列出新增、修改和删除的文件。

**测试结果：**
列出执行的命令及实际结果。

**未解决问题：**
列出遗留问题和风险。

**下一步：**
推荐下一个最小可交付任务。

只有全部验收标准通过，才能将任务标记为 DONE。

完成后停止，不要自动执行下一个任务。
